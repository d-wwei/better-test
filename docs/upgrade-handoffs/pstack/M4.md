## M3: dispatch and resource handoff (integration owner patch)

Before execution, instantiate the existing Dispatch Card in team-role-presets with:
original case/entry/environment shard + overlap reason; frozen source/case/recipe revisions;
target identity + owner + side-effect scope; ports/data/profile/namespace/device/account;
one shared GUI/OS-input driver; time window + bounded wait + release observation;
startup owner + owned cleanup. Keep these in strategy-plan and existing registry,
not a new results protocol or lease service.

Recipe Preconditions/Launch/Doctor bind target and actual isolation; Drive and Wait
requires exclusive shared driver or truly isolated instances; Cleanup is startup owner's
resources only. Never bulk-kill peers by process name. On timeout/crash, reconcile actual
identity and release before changing driver; cannot infer release from time slot expiry.
Readiness/cleanup observations must be actual run artifacts, not natural-language claims.
