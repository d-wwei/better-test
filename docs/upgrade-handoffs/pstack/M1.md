## 已实现的消费接口

只读取解析后的 TEST_ROOT/test-groups.md，识别
`<!-- better-test:case-contract:v1 -->` 后紧邻的 fenced json block。固定字段/类型见
references/test-design-contract.md 与 schemas/test-design.schema.json。

```text
python3 <this-worktree>/scripts/validate-test-design.py --test-root <resolved-root> --format json
```

JSON schema_version=1、scope=design_structure；status 为 valid/not_adopted/invalid。
退出 0=结构合法或未采用，1=结构缺陷/危险本地引用，2=文件/参数操作错误。
必须显示 warnings；valid 带 unresolved、缺 fixture、版本未固定仍不等于可执行/业务通过。
Reference test-root 文件只查存在性；anchor/selector/revision/map ID/语义仍未核验。
不要写第二套 case parser，不要接入结果 verdict，也不要藏进 provider_metadata 当权威 gate。

## M2：strategy 设计检查与来源冲突

I0 后可插入：固定需求/契约/Bug 来源与版本 → 独立列义务/入口/状态 → 对账旧用例 →
复用 native selector 或 opt-in block → checker → 保留 status/errors/warnings → 独立 oracle/
弱断言/重复审查 → 选择可执行环境。not_adopted 仅说明老项目未采用；不强制迁移、不生成
假 stub、不阻断旧项目。结构错误不能混为产品 fail，需求未确认保留 unresolved。

Oracle 按主张选择 authority/scope/revision。原 oracle catalog 的固定 UI>参考>被测对象
排名应退休，目录及失效条件继续保留；来源冲突须记录范围并调查。checker 不判断哪份
来源正确。功能/入口 ID 是引用字符串；M2 审查 surface-manifest 的存在/范围，M1 不另建地图。
UI/API blocks 分别 fixtures/test-design/ui-example.md、api-example.md，请核对 F-/E-/API-/CLI-
引用与地图适配；前缀不强制，示例合成产品未运行。M2 实跑 checker 接入留到 I0，NOT_RUN。

## M3：runner 与 recipe

runner_ref 指原生测试文件/selector；environment_ref 采用
`test-root:env-config.md#OP-NOTES-WEB` 或 `#OP-JOBS`。recipe 由显式 anchor/标题及

或明确 unresolved/not_applicable，不把命令文本升级为可执行引用。请核对两份示例的 recipe
引用与实际模板，I0 再补跨模块验证；M1 未 launch/doctor/Drive 或跑产品。

## M4：独立设计审查最小输入

输入：已固定来源（authority/revision/scope/冲突）、case block 与原生 selector、独立
expected/oracle、feature/entry/状态与风险分母、fixture/env/cleanup 缺口、checker 全输出。
先独立列义务，之后看候选；检验观察点/比较规则/失败含义及哪个错误实现使断言失败。
三份压力材料在 fixtures/test-design/review-scenarios.md；结构 checker 对循环 golden
可返回 valid，语义审查应拒绝，不给系统虚构检测能力。不同 reviewer 不自动产生独立证据。

## M5：哪些变化需复核

来源 revision/scope/权限/契约，前置状态或 fixture 分区，entry/观察路径，expected/归一化/
容差，oracle 的 authority/失效条件，runner selector，environment recipe/cleanup，以及
subject/environment identity 发生相关变化时复核。区分语义变化、纯重构、工具定位变化；
保留原 ID 与旧 run，不因 digest 变化自动改写历史 Pass，也不无条件沿用旧 proof。
checker 是结构/本地存在性检查，不能取代版本、语义、执行/检测 proof 复核。
